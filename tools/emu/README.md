# Тесты в эмуляторе (ZX-M8XXX, headless Chrome)

Эмулятор: `D:\Emulators\ZX\ZX-M8XXX` (переменная `M8XXX_DIR`). Нужны Python + Pillow и Chrome (`EDGE=...` - другой браузер). Каждый запуск поднимает
свой сервер (`serve_emu.py`, порт `EMU_PORT`, по умолчанию 8851) и headless-браузер; **два запуска одновременно не делать** (и вообще на занятой машине
страница иногда не успевает стартовать - `run_emu.py` тогда повторяет запуск сам). Запуск ~25-60 с.

```
python tools/emu/run_emu.py play name=t trd=br_1mb.trd steps=@boot                      # build/br_1mb.trd, Pentagon; сценарий tools/emu/scen/boot.txt
python tools/emu/run_emu.py play name=t trd=br1.trd drive2=br2.trd steps=@two3          # два диска: A: и B:
python tools/emu/run_emu.py play name=t machine=128k beta=1 snow=1 trd=br_1mb.trd steps=@ours1   # Sinclair 128K с Beta Disk, эффект "снега" включён
python tools/emu/run_emu.py play name=t trd=ref/BR_1.TRD drive2=ref/BR_2.TRD machine=128k beta=1 snow=1 steps=@orig1   # оригинал (reference/)
python tools/emu/run_emu.py play name=t trd=br_1mb.trd steps=@play1 hunt=1               # ловец падений: прокрутка + разбор по инструкциям (res.hunt)
```

Результат: `build/emu/<name>.json` (лог, регистры, дампы памяти `mem`, образы дисков `disks`), снимки `build/emu/<name>_<имя>.png`
(`c:имя` - canvas эмулятора с рамкой и снегом; `s:имя` - только экран из ОЗУ). Лог печатается в консоль. Имена файлов `trd=`/`drive2=` - в `build/` (или `ref/..` - в `reference/`).

Шаги сценария (запятые или строки; `#` - комментарий); полный список - в шапке `scripts/play.js`:
`wN` кадры; `Kx` держать клавишу 70 кадров (меню опрашивают редко); `hx:N` держать N кадров; `kx` короткое нажатие; `dx`/`ux`; `c:`/`s:` снимок; `r:` регистры;
`m:имя:ADDR:LEN` дамп; `chk:имя:ADDR:LEN:HEX` проверка PASS/FAIL; `pADDR:VV` poke; `rt:ADDR:MAXFR` идти до PC=ADDR (в ОЗУ ставится ловушка `JR $`);
`ri:имя` до прерывания (PC должен быть BFBF); `tr:имя:N:S` трасса PC/SP/I; `idle:имя:N` детектор зависания; `js:имя:файл` - JS из `scen/js/` (пошаговые трассы, `jumplog`, `save0`, `rdtest`, `ay`...);
`disk:имя:N` образ диска N в json; `boot` сброс+RUN; `fastboot:one|two` см. ниже.

Готовые префиксы: `scen/pre.txt` (логотип -> игра -> меню -> чит 6275 включён; `pre2.txt` - для двух дисков). В чите: `1` уровень -1, `2` уровень +1 (1..17), `3` бессмертие, `6` назад в меню;
главное меню: `1`/`2` новая игра людей/кунгов (потом сложность `1`/`2`), `3` восстановить, `4` в TR-DOS; в игре QAOP + Space.

## Важное про эмулятор
* **`fastboot`** - обходная мера из времён сломанного загрузчика; загрузчик исправлен, сценарии его больше не используют (шаг в play.js остался). Загрузка игры в сценариях: `dEnter`, `w300`, `uEnter` на экране логотипа (Enter при загрузке логотипа = сразу игра).
  (банк 2 <- page5, банк 5 <- page2), и выполняется `#FE00`. Убрать из сценариев, когда загрузчик починят (тогда: `w200` и `Kx` на экране логотипа: `K2` игра, `K1` интро, `K3` инструкция).
* Писать в ОЗУ эмулятора надо **без `await` между записями** (иначе реальный цикл эмулятора успевает пробежать и обнулить банки).
* `callRoutine` для кода, который зовёт ПЗУ TR-DOS, не годится (нет автоподключения ПЗУ) - запускать кадрами (`js/save0.js`, `js/rdtest.js`).
* Снег: в эмуляторе есть (`snow=1`), на Pentagon его нет по определению; на `128k`, `+2` нужен `beta=1` (иначе нет TR-DOS). `+2a`/`+3`: TR-DOS не загружается (диск не читается), только `fastboot`.
