# Чёрный Ворон (Black Raven 1)

Стратегия в реальном времени для ZX Spectrum 128K (Copper Feet / В. Медноногов, 1997-98). Здесь - восстановленные
из авторского архива исходники в виде, который собирается современным ассемблером `sjasmplus` в **обычные диски TR-DOS**
без защиты, без нестандартных секторов и без правки образов вручную.

* `docs/ANALYSIS.md` - как устроен архив, формат дисков 1997 года, защита, прерывания, C++-утилиты, план.
* `docs/NOTES.md` - как устроен проект сейчас: карта памяти, диски, убранная защита, исправление "снега", дисковый слой.

## Что нужно

* Python 3, `sjasmplus` 1.20+ (в PATH или `SJASMPLUS=...`),
* `tools/bin/zx0.exe` (компрессор ZX0, лежит в репозитории; без него используется очень медленный Python-вариант `tools/third_party/zx0`). Холодная сборка около 3,5 минут (упаковка идёт параллельно), повторная - около 10 секунд (кэш `build/cache`).

## Сборка

```
python build.py
```

Результат (каталог `build/`):

| Файл | Что это |
|---|---|
| `br1.trd`, `br2.trd` | два диска TR-DOS по 640 КБ (для настоящего компьютера): диск 1 - загрузчик, заставка, ролики, страницы игры; диск 2 - ресурсы, 34 уровня + 32 дополнительных (1999 г.), сохранения (8 слотов) |
| `br_1mb.trd` | один диск 1 МБ (255 дорожек) для эмуляторов и esxDOS; всё на одном диске, смена диска не запрашивается |
| `two/`, `one/` | промежуточные файлы, листинги `main.lst`, таблицы `main.sym`, раскладка `disk_layout.inc`, `disk1_layout.inc` |

Запуск: загрузить `br1.trd` (или `br_1mb.trd`) в эмулятор и выполнить `RUN` (на диске есть BASIC-файл `boot`).
Игре с двумя дисками при первом запуске нужно сказать, в каком дисководе диск 2 (как и в 1997 году).

## Структура

```
build.py              сборка всего
src/game/             игра (одна сборка, страницы 128K); disk.asm - дисковый слой; main.asm - точка сборки
src/start1/           загрузчик диска 1 (файл br1) + интро + инструкция; disk.asm - чтение секторов
src/final/            концовка (#8000)
src/levels/           34 блока уровней (#79C0); w_117end/w_217end - код концовок
src/lib/dzx0.asm      распаковщик ZX0
src/original/         старый код 1997 года, который в сборку НЕ входит (защита, дисковый слой, LPZ)
assets_src/           РЕДАКТИРУЕМЫЕ ресурсы: PNG, UTF-8 .txt, CSV (править только здесь); build.py превращает их в build/assets/
archive/assets_raw/   прежние двоичные ресурсы автора (эталон только для tools/check_assets.py, не править)
tools/                assets.py, gfx.py, text.py, maps.py, levels.py, check_assets.py - ресурсы (см. ниже); lpz.py, zx0.py, trd.py, fdi.py - форматы; a80conv.py, convert.py - разовый перевод ASM80;
                      verify_original.py - сверка перевода с образами оригинала; patch_crc.py - порт WCRCEXE
work/                 архив промежуточных работ (src_faithful - точный перевод исходников архива, сверен с релизом)
archive/, reference/  материалы (авторский архив; образы оригинальных дисков и порт LW 2024)
docs/                 документация
```

В git-репозитории нет `build/`, `work/`, `archive/` и `reference/`: первые две создаются сборкой, а авторский архив
и образы дисков чужие и здесь не распространяются. Для сборки игры (`python build.py`) они не нужны; нужны только
для сверок `tools/verify_original.py` и `tools/check_assets.py`, их файлы надо положить в эти папки самостоятельно.

## Проверка перевода

`python tools/verify_original.py` пересобирает `work/src_faithful` (побайтно эквивалент архива 1997-98) и сравнивает его
с образами `reference/raven1/RAVEN1.FDI`, `RAVEN2.FDI`: расхождений, не объяснённых известными причинами, нет.

## Ресурсы: как править графику, тексты, карты

`python build.py` сам превращает `assets_src/` в двоичные ресурсы `build/assets/` (около 4 с, пересчёт только при изменениях). Форматы - `docs/FORMATS.md`.

| Что | Файл в `assets_src/` | Заметки |
|---|---|---|
| Цветные заставки уровней | `gfx/screens/barkov/*.png` | не удаляйте `*.orig.scr` рядом: в них скрытые атрибуты; в ячейке 8x8 не более 2 цветов одной яркости |
| Экраны интро/инструкции | `gfx/screens/{intro,instr}/*.png` | чёрный = чернила, 256x192 |
| Ландшафт, герои, кнопки, панель, шрифт, имена | `gfx/land`, `gfx/heroes`, `gfx/buttons`, `gfx/panel/wbar.png` | рисовать только в местах блоков (раскладка как у автора); спрайты героев - 4 цвета (чёрный - чернила, голубой - силуэт, белый - прозрачно); размер листа менять нельзя |
| Кадры интро и роликов | `gfx/intro`, `gfx/flick/flick_?.png` | размеры кадров фиксированы |
| Тексты | `text/*.txt` | кодировка UTF-8; символа нет в шрифте - сборка остановится с номером строки; латинские и кириллические буквы одной формы - разные глифы (`docs/FORMATS.md`, п. 3); ширина строк: ролики 13, титры 12, задания ровно 20 глифов между вертикальными чертами; инструкция - сжатие и словарь считаются сами |
| Карты и герои | `maps/*.csv`, `maps/*.her.txt` | `*.png` - только просмотр; обновить: `python tools/assets.py preview` |
| Доп. уровни 1999 г. | `levels_ext/` | входят в сборку (выбор набора в меню новой игры); блоки строит `build.py` через `tools/levels.py`; музыка - `assets_src/music/ext` |
| Музыка | `music/` | двоичная, правке не подлежит |

Проверка: `python tools/check_assets.py` (круг `assets_src` -> двоичные -> сверка с `archive/assets_raw`); после своих правок п. [1] покажет отличия от эталона - это нормально. Эталон не править.
